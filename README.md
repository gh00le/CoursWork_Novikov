# Сравнительный анализ производительности SPA и MPA

Курсовая работа на тему:

**«Сравнительный анализ производительности SPA и MPA: разработка прототипа интернет-магазина на React и Next.js»**

## Описание проекта

Проект разрабатывается в рамках курсовой работы и предназначен для сравнительного анализа двух подходов к построению современных веб-приложений:

- SPA (Single Page Application) на React;
- MPA (Multi Page Application) на Next.js с использованием возможностей серверного рендеринга.

В рамках исследования разрабатываются два прототипа интернет-магазина с одинаковой функциональностью и общей серверной частью.

Обе версии приложения используют единый REST API, реляционную базу данных Microsoft SQL Server и NoSQL-хранилище Redis.

Это позволяет проводить сравнение SPA и MPA в максимально одинаковых условиях.

## Цель исследования

Целью работы является исследование особенностей и производительности SPA- и MPA-подходов на примере двух реализаций прототипа интернет-магазина.

Для достижения поставленной цели необходимо:

- разработать общую серверную часть приложения;
- разработать SPA-версию интернет-магазина на React;
- разработать MPA-версию интернет-магазина на Next.js;
- обеспечить одинаковую функциональность обеих версий;
- использовать реляционную SQL-базу данных;
- использовать NoSQL-хранилище;
- настроить автоматическую проверку и сборку проекта;
- провести серию тестов производительности;
- собрать и структурировать результаты;
- выполнить сравнительный анализ полученных данных.

## SPA

Каталог `spa` предназначен для реализации одностраничной версии интернет-магазина на React.

После первоначальной загрузки приложения основные переходы между страницами выполняются на стороне клиента без полной перезагрузки HTML-документа.

Для клиентской маршрутизации планируется использовать React Router.

SPA получает необходимые данные через общий REST API, реализованный на FastAPI.

## MPA

Каталог `mpa` предназначен для реализации версии интернет-магазина на Next.js.

В рамках данной реализации планируется использовать возможности Next.js для серверного формирования страниц и предварительной генерации содержимого.

Для интерактивных компонентов будет использоваться клиентская гидратация.

MPA работает с тем же FastAPI REST API, что и SPA.

Использование общего backend необходимо для обеспечения одинаковых условий проведения экспериментов.

## Backend

Каталог `backend` содержит общую серверную часть приложения, разработанную на FastAPI.

Backend предоставляет REST API для SPA- и MPA-версий интернет-магазина.

Через серверную часть осуществляется:

- получение каталога товаров;
- получение информации об отдельном товаре;
- фильтрация товаров;
- работа с корзиной;
- оформление заказа;
- взаимодействие с Microsoft SQL Server;
- взаимодействие с Redis;
- обработка и передача данных клиентским приложениям.

Использование единого backend позволяет минимизировать влияние серверной части на результаты сравнения SPA и MPA.

## Работа с данными

В проекте используются два типа систем хранения данных:

1. Реляционная SQL-база данных — Microsoft SQL Server.
2. NoSQL-хранилище — Redis.

Такой подход позволяет продемонстрировать совместное использование SQL- и NoSQL-технологий в рамках одного веб-приложения.

### Microsoft SQL Server

Microsoft SQL Server используется как основная постоянная база данных приложения.

В MSSQL планируется хранить:

- товары;
- категории товаров;
- характеристики товаров;
- цены;
- информацию о заказах;
- позиции заказов;
- другие постоянные данные интернет-магазина.

Microsoft SQL Server отвечает за долговременное хранение структурированных данных и обеспечение связей между сущностями.

Пример структуры:

```text
Products
Categories
Orders
OrderItems
```

Для взаимодействия FastAPI с Microsoft SQL Server планируется использовать ORM или соответствующий драйвер подключения к базе данных.

### Redis

Redis используется в проекте как NoSQL-хранилище типа «ключ — значение».

Redis не заменяет основную SQL-базу данных, а применяется совместно с Microsoft SQL Server.

Основное назначение Redis в проекте:

- кэширование часто запрашиваемых данных;
- кэширование каталога товаров;
- кэширование отдельных карточек товаров;
- хранение временных данных;
- хранение пользовательских сессий;
- при необходимости — временное хранение содержимого корзины.

Пример логики получения каталога:

```text
Запрос клиента
      ↓
FastAPI
      ↓
Проверка данных в Redis
      ↓
┌──────────────────────────┐
│ Данные есть в Redis?     │
└───────────┬──────────────┘
            │
       Да   │   Нет
            │
            ▼
      Возврат данных        Запрос в MSSQL
                                  ↓
                           Получение данных
                                  ↓
                           Запись в Redis
                                  ↓
                           Возврат клиенту
```

Использование Redis позволит дополнительно исследовать влияние кэширования на скорость обработки запросов.

- оформление заказа;
- получение данных с backend;

- обработку основных пользовательских действий.

## REST API

Серверная часть разрабатывается на FastAPI.

Планируется реализовать REST API для основных функций интернет-магазина.

Пример предполагаемых маршрутов:

```text
GET    /products
GET    /products/{id}
GET    /categories
GET    /cart
POST   /cart
DELETE /cart/{id}
POST   /orders
```

Один и тот же API используется SPA- и MPA-версиями приложения.

Работа с постоянными данными выполняется через Microsoft SQL Server, а Redis используется для хранения временной информации и кэширования.

## Исследование производительности

После завершения разработки обе версии интернет-магазина будут протестированы в одинаковых условиях.

Для анализа планируется использовать:

- Chrome DevTools;
- Lighthouse;
- Lighthouse CI;
- WebPageTest;
- Web Vitals;
- пользовательские скрипты для автоматизированного сбора метрик.

Исследование будет проводиться при различных условиях сетевого подключения, включая моделирование:

- 3G;
- 4G;
- Wi-Fi.

## Исследуемые показатели

В ходе сравнительного анализа планируется измерять:

- Time to First Byte (TTFB);
- First Contentful Paint (FCP);
- Largest Contentful Paint (LCP);
- Cumulative Layout Shift (CLS);
- Interaction to Next Paint (INP);
- время первоначальной загрузки;
- время перехода между страницами;
- размер JavaScript-бандла;
- объём передаваемых данных;
- количество сетевых запросов;
- особенности загрузки ресурсов;
- показатели интерактивности;
- SEO-показатели.

Дополнительно может быть исследовано влияние Redis-кэширования на:

- время ответа REST API;
- количество обращений к MSSQL;
- скорость получения каталога товаров;
- скорость повторных запросов.
